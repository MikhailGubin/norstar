# Веб-приложение "Norstar"

## Описание:      
    Данное веб-приложение трекером задач для сотрудников.
    Содержит два отдельных приложения приложения: 
    "tasks" - приложение, в котором прописана основная логика приложения;    
    "users" - приложение для регистрации и авторизации пользователей, а также для настройки доступа для 
    авторизированных пользователей. Также в данном приложении содержится информация о платежах пользователей.

## Установка и настройка

### Предварительные требования

*   [Git](https://git-scm.com/downloads)
*   [Docker](https://docs.docker.com/get-docker/)
*   [Docker Compose](https://docs.docker.com/compose/install/)

### Клонирование репозитория

```bash
git clone git@github.com:MikhailGubin/norstar.git
cd <название_папки_проекта>
```
### Настройка переменных окружения

Скопируйте файл .env.example и заполните его:

```
cp .env.sample
```

Откройте .env в текстовом редакторе и настройте переменные.


Совет: Для генерации SECRET_KEY вы можете использовать команду Python:

```
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

### Запуск проекта
С помощью Docker Compose
Для запуска всех сервисов (PostgreSQL, Redis, Django Web):

```
docker-compose up -d --build
```

### Проверка работоспособности

#### Веб-приложение
Откройте браузер и перейдите по адресу: http://localhost:8000

#### Сервисы
    PostgreSQL:
    к базе данных, используя переменные из вашего `.env` файла:
    postgresql://${POSTGRES_USER}:${POSTGRES_PASSWORD}@localhost:5432/${POSTGRES_DB}
    Проверьте логи контейнера: 
```
docker-compose logs db
```

    Redis:
    Проверьте логи контейнера: 
```
docker-compose logs redis
```

### Остановка проекта

    Остановка контейнеров
```
    docker-compose down
```

    Остановка и удаление данных (Полный сброс)
    ВНИМАНИЕ: Эта команда удалит все данные PostgreSQL и Redis!
```
docker-compose down -v
```

## Описание приложений:

1. #### Приложение mailing_service 
##### Описание:        
    Создана модель "Задание" со следующими полями:
    
    * Владелец — пользователь, создавший задание (менеджер/руководитель)
    * Исполнитель — сотрудник, ответственный за выполнение задания
    * Наименование — краткое описание задачи
    * Описание — детальное описание требований к задаче
    * Родительская задача — связь с родительским заданием для создания иерархии задач
    * Статус — этап выполнения задачи (создана, требует уточнения, в работе, на проверке, выполнена, отменена)
    * Приоритет — уровень важности задачи (низкий, средний, высокий)
    * Срок выполнения — дата и время дедлайна 
    * Время создания — автоматически заполняемая метка времени
    * Время начала работы — момент взятия задачи в работу
    * Время завершения — момент окончания задачи
    
    Реализованы CRUD-операции для модели Задания с использованием APIView.
    Добавлены следующие валидаторы:
    * Срок выполнения не может быть раньше чем через 1 час от текущего времени    
    * Родительской задачей не может быть уже завершенная задача
    * Запрещены циклические зависимости между задачами
    * Нельзя менять исполнителя для задачи в работе
    
    Реализованы специальные эндпоинты для аналитики:
    * Занятые сотрудники — список сотрудников, отсортированный по количеству активных задач
    * Важные задачи — задачи, не взятые в работу, но от которых зависят другие активные задачи. В данном эндпоинте
    происходит подбор наименее загруженных сотрудников.
    
    Для вывода списка задач реализована пагинация с выводом по 5 заданий на страницу.
    Проект содержит комплексные тесты, проверяющие CRUD-операции и бизнес-логику.
        
   
2. #### Приложение users 
##### Описание: 
    Создана модель «Пользователь» со следующими полями:   
    * Все поля от обычного пользователя, но авторизацию реализована по полю email;         
    * Город - город проживания сотрудника,
    * Фамилия — фамилия сотрудника
    * Имя — имя сотрудника  
    * Отчество — отчество сотрудника (опционально)
    * Должность — занимаемая должность в компании
    * Аватар — фотография сотрудника
    * Телефон — контактный номер телефона
        
    Электронная почта используется как поле для авторизации.
    Созданы CRUD для модели Пользователь. Для реализации CRUD использовано APIView.
    Каждый эндпоинт в проекте закрыт авторизацией, кроме регистрации и авторизации пользователей.
    В данном проекте использована JWT-авторизация.    
    Электронная почта используется как основное поле для авторизации.
    Реализована JWT-аутентификация с использованием Simple JWT.
    Созданы эндпоинты для регистрации, авторизации и управления профилем.
    
    Настроены права доступа:
    * Руководители могут создавать задачи для любого сотрудника, имеют полный доступ ко всем данным.
    * Сотрудники видят только свои задачи, могут регистрировать свой профиль.  
    * Гости могут только зарегистрироваться или авторизоваться.
